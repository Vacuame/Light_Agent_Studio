# My Agent Studio

这是一个轻量级 Agent 工作流框架，用来把一个通用 AI 助手拆成几个清晰角色，并通过文件完成协作、交接、记忆和质量检查。

## 核心思路

```text
规则层：规定怎么工作
角色层：规定谁来工作
技能层：规定某类任务怎么做
状态层：用轻量树形任务目录记录 overview、Agent 工作区、handoff 和 report
产物层：保存已经确认的项目事实
质量门：决定关键产物能不能交接、回报或关闭
自动护栏：提醒、检查、防止忘记重要步骤
```

## 常见工作流

Agent Studio 支持按任务需要裁剪流程。常见链路是：

```text
理解项目 -> 架构设计 -> 模块设计 -> 程序实现 -> 审查 -> 测试 -> 回报/交接/关闭
```

这不是强制串行流程。任务结构、角色分配和是否拆分 Agent 工作区由用户或当前父级 Agent 决定。一个 Agent 可以兼任多个角色，一个任务也可以只有一个工作区。

对应技能：

```text
/start
/understand
/architecture
/module-design
/implement
/review
/test
/handoff
```

## 启动提示词

把 `Agent_Studio` 放入某个项目后，可以在新会话中直接复制这段话：

```text
你现在在这个项目中工作。

请先阅读 `Agent_Studio/rules/rules.md`。

如果当前角色不明确，按 rules 中定义的启动规则读取必要文件并判断或询问当前角色。
如果当前角色明确，读取对应 `Agent_Studio/agents/<role>.md`，并按角色文件里的 `## 角色加载清单` 继续。

启动后请告诉我：
1. 你理解的当前任务是什么
2. 你匹配到的顶层任务目录是什么，或是否需要我确认创建
3. 你当前应使用或创建哪个 Agent 工作区
4. 缺少哪些项目信息或任务信息
5. 建议由哪个角色接手
6. 建议使用哪个 skill
7. 下一步需要我确认什么

规则、状态、角色、skill、质量门和产物的读取顺序全部由 rules 决定。

未经我确认，不要修改项目代码、状态层或产物层。
顶层任务目录只能在我明确要求开启任务时创建；如果找不到匹配任务目录，必须先问我。
交接写对应 Agent 工作区的 handoff.md，回报写对应 Agent 工作区的 report.md。
```

## 日常角色提示词

如果你想在日常使用中让 Agent 以某个已有角色接手，只需要填角色名和当前任务描述。不要手动填写任务目录路径，让 Agent 自己根据 `state/tasks/` 的目录树、`overview.md` 和 handoff/report 定位。

```text
你现在是 [角色名]。

当前任务：
[用自然语言写清楚你要它接手的任务。可以说明这是架构任务、模块任务、程序任务、测试任务、审查任务、父任务、某个子工作区或旁支辅助任务；不需要写任务目录路径。]

请先阅读：
1. Agent_Studio/rules/rules.md
2. 根据你现在的角色名，在 Agent_Studio/agents/ 中自行找到对应角色文件并阅读

然后按 `Agent_Studio/rules/rules.md` 的工作前读取规则、当前角色文件的 `## 角色加载清单`、以及 `Agent_Studio/rules/context-rules.md` 的任务定位规则，在 `Agent_Studio/state/tasks/` 中定位最匹配的顶层任务目录和 Agent 工作区。

定位要求：
1. 不要要求我手动输入任务目录路径，除非目录树和任务描述都无法区分。
2. 如果无法唯一定位顶层任务或 Agent 工作区，列出候选项和判断依据，不要擅自选择。
3. 如果没有匹配顶层任务，询问我是否创建新任务目录；不要自行创建顶层任务。
4. 如果顶层任务明确但没有匹配工作区，说明建议创建的位置和原因，等我确认后再创建。

定位到当前 Agent 工作区后，请读取：
- 顶层任务 overview.md
- 当前工作区 handoff.md，如果存在
- 当前工作区 report.md，如果存在
- 必要的父级/子级/兄弟工作区 report
- 相关 docs/ 或源码文件

请先告诉我：
1. 你理解的任务是什么
2. 你判断自己应接手哪个顶层任务和 Agent 工作区，以及判断依据
3. 如果无法唯一定位，候选项有哪些
4. 你当前角色需要读取哪些项目文件
5. 是否缺少关键信息
6. 是否可能需要 handoff.md，以及是否需要我确认写入
7. 如果后续需要向上留痕，可能应回报给谁
8. 当前最小下一步

未经我确认，不要修改项目代码、状态层或产物层。
如果 rules 没有告诉你下一步该读取什么，先向我确认，不要自行猜路径。
```

常用对应关系：

```text
Administrator：修改 Agent 架构、规则、角色、技能、项目配置
Architect：理解项目整体、判断架构、建立模块地图
Module Designer：拆模块、定义接口、数据流和验收标准
Developer：根据模块设计实现代码
Tester：测试、验收、记录 bug 和关闭建议
Adviser：回答问题、解释代码、在用户要求时整理辅助理解材料
```

如果你是想“新增一个从未定义过的角色”，不要直接让新角色工作，先用 Administrator：

```text
你现在是 Administrator。
我想为 Agent Studio 新增一个角色：[新角色名]。
请先阅读 rules/rules.md，并按 rules 中定义的管理流程评估这次角色变更。
先评估这个角色是否真的需要新增、会影响哪些规则和技能、建议放哪些职责边界。
未经我确认，不要创建或修改角色文件。
```

## 目录说明

```text
rules/
  系统规则、上下文规则、协作规则、项目配置、质量门、自动护栏

agents/
  Administrator、Architect、Module Designer、Developer、Tester、Adviser

skills/
  每类任务的 SOP

state/tasks/
  用户明确开启的顶层任务目录；每个任务包含 overview.md、嵌套 Agent 工作区，以及用户要求或确认后的任务级 docs/*.md

docs/
  项目总览、架构、模块地图、模块设计、技术决策、实现记录、测试记录
```

## 使用原则

1. 开始任务前，先读 `Agent_Studio/rules/rules.md`，再按 rules 指引读取状态、角色、skill、质量门和产物文件。
2. 顶层任务目录只能在用户明确要求开启任务时创建。
3. 每个 Agent 窗口必须定位或创建自己的 Agent 工作区。
4. 目录树就是索引：父子关系由嵌套文件夹表达，同级文件夹表示并列或旁支。
5. 不清楚就问，不允许用猜测替代决策。
6. 需要写入临时协作信息、交接、回报、任务级 docs 或 overview 时，先说明拟写内容，用户确认后再写入对应状态层文件。
7. 已确认的长期事实写到全局 `docs/`。
8. `overview.md` 是顶层任务总览，只写跨角色稳定共识；`handoff.md` 是工作区交接；`report.md` 是工作区回报。
9. 关键产物准备交接、准备向上留痕、或准备支持关闭判断前，检查对应质量门。
10. 修改规则、角色、技能时，必须走 Administrator 和管理门。
