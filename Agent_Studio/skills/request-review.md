# Skill: request-review

用于当前 Agent 把自己的关键结论交给 Reviewer 子 Agent 做独立证伪审查。

## 目标

- 让承载下游决策的结论在交接、回报或关闭前经过一次独立审查
- 审查者与当前 Agent 上下文隔离，避免自我锚定

## 权限

本 skill 不授予额外权限；执行者必须遵守当前角色文件中的权限边界。

## 使用时机

- 结论将支撑高影响决策（架构方向、大规模重构、删除旧系统）
- 结论包含否定性或全称断言（"没有""只能""全部""从未"）、"死代码"判定
- 用户或任务 owner 明确要求审查

本 skill 是按需技能，不是必经环节。

## 任务输入

- 当前 Agent 已按 `rules/rules.md` 结论纪律整理的结论条目

## 流程

1. 整理本次要送审的结论条目。
2. 在当前 Agent 自己工作区写入 `待审查结论.md`（临时文件，每次送审覆盖即可）。写入确认机制见 `rules/collaboration-rules.md`。
3. 创建子 Agent 执行审查。创建指令只包含角色和任务文件路径，例如：

```text
你是 Reviewer。审查 <当前工作区路径>/待审查结论.md。
```

子 Agent 的启动读取、行为边界和返回格式由 `agents/reviewer.md` 定义，创建指令中不重复。

4. 等待子 Agent 返回审查结果。
5. 在对话中向用户汇报：双方一致的条目直接过；分歧条目将双方观点和依据并列呈现，交用户裁决。

审查结果不留痕，存在于对话中即可。

## 待审查结论.md 格式

```markdown
# 待审查结论

## 结论 1

结论：
依据：文件:行 / 命令 / 测试
确定性：高 / 中 / 低

## 结论 2

结论：
依据：文件:行 / 命令 / 测试
确定性：高 / 中 / 低
```

只写结论条目：结论、依据、确定性。

禁止写入：

- 任务背景、探索过程、心路叙事
- 对结论的自我辩护或补充解释
- 给审查者的任何指引（审查重点、怀疑方向、方法建议）

审查者如何审查由 `agents/reviewer.md` 和 `skills/review-conclusions.md` 定义，本 skill 不重复。

## 禁止

- 不把结论内容塞进子 Agent 创建指令；指令只给路径，结论以文件为准。
- 不代替子 Agent 下审查结论。
- 不因为审查通过就跳过质量门；审查通过是质量门的输入之一，不替代质量门。
