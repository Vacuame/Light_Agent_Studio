# Skill: request-challenge

用于当前 Agent 把设计交付物交给 Challenger 子 Agent 做前提质询。

## 目标

- 让设计方案在定稿或用户确认前，经过一次来自独立上下文的质询
- 质询者不继承当前 Agent 的方案叙述和推理过程，避免自我锚定

## 权限

本 skill 不授予额外权限；执行者必须遵守当前角色文件中的权限边界。

## 使用时机

- 架构设计、模块设计起草完成，准备通过质量门或交用户确认前
- 实现计划拟交用户确认前
- 用户或任务 owner 明确要求质询时

用户明确豁免的单次交付可跳过；跳过时在交付说明中标注"未经质询"。

环境不具备子 Agent 能力时，退化为：当前 Agent 在交付说明中逐条自答 `skills/challenge-design.md` 的质询问题集，并标注"自答，未经独立质询"。

## 任务输入

- 本次设计交付物：设计目标、设计方案、方案理由

## 流程

1. 在当前 Agent 自己工作区写入 `待质询设计.md`（临时文件，每次送质询覆盖即可）。写入确认机制见 `rules/collaboration-rules.md`。
2. 创建子 Agent 执行质询。创建指令只包含角色和任务文件路径，例如：

```text
你是 Challenger。质询 <当前工作区路径>/待质询设计.md。
```

子 Agent 的启动读取、行为边界和返回格式由 `agents/challenger.md` 定义，创建指令中不重复。不要把设计内容或方案理由塞进创建指令；指令只给路径。

3. 等待子 Agent 返回质询结果。
4. 在对话中向用户汇报：质询意见与设计一致的部分直接过；有疑问的部分，把设计方观点与质询方依据并列呈现，交用户裁决。汇报以子 Agent 返回为准，不代替它下质询结论。
5. 质询意见被采纳时修订设计；不采纳时在交付说明中记录理由。

质询结果不留痕，存在于对话中即可。

## 待质询设计.md 格式

```markdown
# 待质询设计

## 设计目标

（要解决什么，目标来自哪里）

## 设计方案

（落点、结构、步骤——方案本身）

## 方案理由

（为什么这样设计）
```

只写设计本身。禁止写入：

- 探索过程、心路叙事、被否决的候选方案
- 对方案的自我辩护或补充解释
- 给质询者的任何指引（质询重点、怀疑方向、方法建议）

质询者如何质询由 `agents/challenger.md` 和 `skills/challenge-design.md` 定义，本 skill 不重复。

## 禁止

- 不因质询通过就跳过质量门；质询通过是质量门的输入之一，不替代质量门。
