# Skill: review-conclusions

用于 Reviewer 子 Agent 审查 `待审查结论.md`。

## 常见执行角色

- Reviewer（子 Agent）

## 权限

本 skill 不授予额外权限；执行者必须遵守当前角色文件中的权限边界。本 skill 全程只读，不写入任何文件。

## 任务输入

- 父 Agent 工作区的 `待审查结论.md`（路径由父 Agent 在创建子 Agent 时给出）
- 结论条目中列出的依据（源码、配置、命令输出等），按需核实

## 流程

1. 读取 `待审查结论.md`。
2. 逐条处理结论条目：
   - 核查依据：依据指向的 文件:行 / 命令 / 配置 是否真实存在，且是否真的支持该结论。
   - 否定性与全称结论（"没有""不存在""只能""全部""从未"）：必须自己做一次反证搜索（跨包、跨目录普查；换关键词；查基类与范本），排除范围不足时不能判 PASS。
   - 确定性标注为"中/低"的条目：检查标注是否如实，不把低确定性条目当成已证实。
3. 条目无依据、依据失效或信息不足无法判定时，标"无法判定"并说明原因，不猜。
4. 汇总逐条结果，按 `agents/reviewer.md` 的输出格式返回父 Agent。

## 审查标准

结论是否达标，以 `rules/rules.md` 结论纪律为准：有确定性标注和依据，否定性结论有排除范围，侧翼结论已升级为正式条目。

## 结论格式

```text
PASS：依据真实存在且支持结论；否定性断言已做反证搜索且排除范围合理
CONCERNS：依据存在但只覆盖部分情形，或排除范围偏窄但未发现反例
BLOCKED：依据不存在、依据不支持结论、发现反例，或确定性标注明显虚高
无法判定：缺少审查所需信息，已说明原因
```

## 禁止

- 不写入、不修改任何文件。
- 不因文件格式工整、引用密集而放松核查。
- 不把"没发现问题"当成 PASS 的理由；PASS 必须基于实际做过的复核动作。
- 不扩展到结论条目之外的审查。
