# 开发门

适用于检查代码实现类交付物。

结论格式见 `rules/quality-gates.md`。角色权限见当前 `agents/<role>.md`。

## 适用交付物

- 代码实现
- 实现说明
- 给 Tester 的测试交接
- 实现阶段回报

## 使用时机

当代码实现准备交给测试、下游 Agent 或准备向上回报前使用。

## 检查清单

- 代码是否按模块设计实现？
- 代码是否遵守模块设计中的实现落点？
- 新增 API 是否位于正确层级？
- 是否避免向基础类、系统类或 Manager 类添加具体功能门面方法？
- 如果修改了基础类、系统类或 Manager 类 API，是否证明这是该层级核心职责并获得确认？
- 具体能力是否优先由组件、接口、专门服务或明确模块 owner 承接？
- 是否偏离设计？
- 如果偏离设计、实现落点或层级边界，是否记录原因并等待确认？
- 是否更新实现说明？
- 是否有明显风险？
- 是否需要更新架构或模块设计？
- 是否提供给 Tester 的测试入口？
- 是否提供给 Tester 的注意事项？
- 是否有未完成项或 TODO？
- 如果写 `handoff.md`，测试入口、风险和下一步是否清楚？
- 如果写 `report.md`，实现结果、验证情况、未完成项和对上层任务的影响是否清楚？

## 输出要求

交接或回报前必须给出：

```text
实现内容：
修改文件：
实现落点遵循情况：
层级边界检查：
偏离设计：
风险：
未完成项：
给 Tester 的测试入口：
任务目录：
handoff/report：
建议结论：PASS / CONCERNS / BLOCKED
```
