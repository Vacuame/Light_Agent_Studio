# 模块门

适用于模块设计交给开发前。

## 谁需要读

- Module Designer
- 使用 `skills/module-design.md` 时的执行者

## 检查清单

- 模块目标是否清楚？
- 上游依赖是否清楚？
- 下游影响是否清楚？
- 输入是否清楚？
- 输出是否清楚？
- 接口是否清楚？
- 数据流是否清楚？
- 实现文件或目录是否清楚？
- 归属类、组件、模块或服务是否清楚？
- 建议新增或修改的方法、事件、接口或配置点是否清楚？
- 调用入口和数据流出口是否清楚？
- 不应放置的位置是否写清楚？
- 不确定点是否明确标为 `待确认`？
- 边界情况是否清楚？
- 不做什么是否写清楚？
- 验收标准是否清楚？
- Developer 是否能据此实现？
- Developer 是否无需自行决定代码层级？
- Tester 是否能据此测试？

如果缺少实现落点，不能给出 `PASS`。实现落点部分缺失但可由 Developer 小范围确认时，最多给出 `CONCERNS`；如果会影响代码层级或模块边界，必须给出 `BLOCKED`。

## 输出要求

交接前必须给出：

```text
模块名称：
实现范围：
输入输出：
接口：
实现落点：
边界情况：
验收标准：
给 Developer 的说明：
给 Tester 的提示：
建议结论：PASS / CONCERNS / BLOCKED
```
