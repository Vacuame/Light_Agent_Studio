# 模块门

适用于检查模块设计类交付物。

结论格式见 `rules/quality-gates.md`。角色权限见当前 `agents/<role>.md`。

## 适用交付物

- 模块设计说明
- 模块接口、输入输出、数据流说明
- 给 Developer 或 Tester 的模块交接
- 模块阶段回报

## 使用时机

当模块设计准备交给开发、测试、下游 Agent 或准备向上回报前使用。

## 检查清单

- 模块目标是否清楚？
- 上游依赖是否清楚？
- 下游影响是否清楚？
- 输入是否清楚？
- 输出是否清楚？
- 接口是否清楚？
- 数据流是否清楚？
- 实现文件或目录是否清楚？
- 归属类、组件、模块或服务是否清楚？
- 建议新增或修改的方法、事件、接口或配置点是否清楚？
- 调用入口和数据流出口是否清楚？
- 不应放置的位置是否写清楚？
- 不确定点是否明确标为 `待确认`？
- 实现落点的判断是否基于已验证事实？引用的事实结论是否有确定性标注？
- 边界情况是否清楚？
- 不做什么是否写清楚？
- 验收标准是否清楚？
- Developer 是否能据此实现？
- Developer 是否无需自行决定代码层级？
- Tester 是否能据此测试？
- 如果写 `handoff.md`，接手对象、实现落点、风险和下一步是否清楚？
- 如果写 `report.md`，模块设计结论、未完成项、风险和对上层任务的影响是否清楚？

## 判定档位

- `PASS`：目标、输入输出、接口、数据流、实现落点、验收标准清楚，Developer 无需自行决定代码层级。
- `CONCERNS`：实现落点部分缺失，但可由 Developer 小范围确认，且不影响代码层级或模块边界。
- `BLOCKED`：缺少实现落点，或不确定点会影响代码层级或模块边界。

## 输出要求

交接或回报前必须给出：

```text
模块名称：
实现范围：
输入输出：
接口：
实现落点：
边界情况：
验收标准：
给 Developer 的说明：
给 Tester 的提示：
任务目录：
handoff/report：
建议结论：PASS / CONCERNS / BLOCKED
```
