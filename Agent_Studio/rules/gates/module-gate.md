# 模块门

适用于模块设计交给开发前。

## 谁需要读

- Module Designer
- 使用 `skills/module-design.md` 时的执行者

## 检查清单

- 模块目标是否清楚？
- 上游依赖是否清楚？
- 下游影响是否清楚？
- 输入是否清楚？
- 输出是否清楚？
- 接口是否清楚？
- 数据流是否清楚？
- 边界情况是否清楚？
- 不做什么是否写清楚？
- 验收标准是否清楚？
- Developer 是否能据此实现？
- Tester 是否能据此测试？

## 输出要求

交接前必须给出：

```text
模块名称：
实现范围：
输入输出：
接口：
边界情况：
验收标准：
给 Developer 的说明：
给 Tester 的提示：
建议结论：PASS / CONCERNS / BLOCKED
```
