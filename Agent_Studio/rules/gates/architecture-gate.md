# 架构门

适用于检查架构类交付物。

结论格式见 `rules/quality-gates.md`。角色权限见当前 `agents/<role>.md`。

## 适用交付物

- 架构设计说明
- 技术路线说明
- 模块边界和依赖说明
- 给模块设计、子任务或下游 Agent 的架构交接
- 架构阶段回报

## 使用时机

当架构设计准备交给模块设计、子任务、下游 Agent 或准备向上回报前使用。

## 检查清单

- 项目目标是否清楚？
- 技术路线是否清楚？
- 模块边界是否清楚？
- 模块依赖关系是否清楚？
- 是否存在明显循环依赖？
- 关键风险是否记录？
- 关键事实断言是否有确定性标注和依据？否定性断言（如"框架没有/只能 X"）是否有排除范围？
- 是否需要重要技术决策记录？
- Module Designer 或下游任务是否能据此继续？
- 如果写 `handoff.md`，接手对象、必读文件、风险和下一步是否清楚？
- 如果写 `report.md`，架构结论、未完成项、风险和对上层任务的影响是否清楚？

## 输出要求

交接或回报前必须给出：

```text
架构结论：
模块边界：
依赖关系：
关键风险：
需要补充的决策：
任务目录：
handoff/report：
建议结论：PASS / CONCERNS / BLOCKED
```
