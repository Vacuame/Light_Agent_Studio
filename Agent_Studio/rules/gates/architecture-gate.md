# 架构门

适用于架构设计交给模块设计前。

## 谁需要读

- Architect
- 使用 `skills/architecture.md` 时的执行者

## 检查清单

- 项目目标是否清楚？
- 技术路线是否清楚？
- 模块边界是否清楚？
- 模块依赖关系是否清楚？
- 是否存在明显循环依赖？
- 关键风险是否记录？
- 是否需要重要技术决策记录？
- Module Designer 是否能据此继续拆模块？

## 输出要求

交接前必须给出：

```text
架构结论：
模块边界：
依赖关系：
关键风险：
需要补充的决策：
建议结论：PASS / CONCERNS / BLOCKED
```
