# 质量门

质量门是关键产物交接前的检查点。

它不检查“角色本人”，而是检查“产物能不能交给下一个环节”。

## 管理门

适用于修改规则、角色、技能、项目配置。

检查：

- 为什么要改？
- 会影响哪些角色？
- 会影响哪些技能？
- 是否需要同步更新质量门？
- 是否需要迁移旧文档？
- 是否可能造成旧流程失效？

结论：

```text
PASS：可以修改
CONCERNS：可以修改，但记录风险
BLOCKED：不能修改，先补充方案
```

## 架构门

适用于架构设计交给模块设计前。

检查：

- 模块边界清楚吗？
- 技术路线清楚吗？
- 依赖关系清楚吗？
- 关键风险有记录吗？
- 是否需要重要技术决策记录？

## 模块门

适用于模块设计交给开发前。

检查：

- 模块目标清楚吗？
- 输入输出清楚吗？
- 接口清楚吗？
- 数据流清楚吗？
- 边界情况清楚吗？
- 验收标准清楚吗？
- Developer 能否据此实现？
- Tester 能否据此测试？

## 开发门

适用于代码交给测试前。

检查：

- 代码是否按模块设计实现？
- 是否偏离设计？如果偏离，是否记录原因？
- 是否更新实现说明？
- 是否有明显风险？
- 是否需要更新架构或模块设计？
- 是否提供给 Tester 的测试入口和注意事项？

## 测试门

适用于任务关闭前。

检查：

- 测试是否执行？
- 测试是否通过？
- bug 是否记录？
- 未解决问题是否写清楚？
- 是否可以关闭任务？

## 顾问产物门

适用于 Adviser 写入供其他 Agent 阅读的文件前。

检查：

- 是否清晰易懂？
- 是否标明来源？
- 是否区分事实、推测、建议？
- 是否注明不是权威设计？
- 是否有过期风险？
